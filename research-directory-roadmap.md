Количество в памятке относится к выбранному выезду. Для пищевых проб дополнительно показывать требования к массе, объёму и условиям отбора из карточки, когда они есть. Для смывов сохранять оба набора и их количества. Инструментальные измерения для первой версии можно указать отдельными строками вручную с числом рабочих мест, периодичностью и при необходимости пунктом прейскуранта. Решение о добавлении измерений в каталог ради автоматической подстановки пунктов остаётся открытым.

**Опросник.** Готовое блюдо и отдельно отбираемый ингредиент задают разные объекты исследования. Вопросы для пилота уточняют, что отбирают, есть ли рыба или только водные беспозвоночные, была ли обработка после смешивания, есть ли заправка и консерванты.

### 12. Перечень исследований для заявления

- Из карточки добавить пробу в черновик, указать рабочее название пробы и отметить нужные исследования. Поддержать несколько проб, в том числе две из одной категории. Выбор хранить в одном списке черновика, который затем используют заявление и памятка. При добавлении, изменении и удалении позиции сразу пересчитывать предпросмотр.
- На каждую пробу формировать одну строку. Объединять пункты одного раздела, убирать повторы в пределах раздела и сохранять дробные номера. Номера разделов выводить римскими цифрами. Для выбранной микробиологической группы добавлять подтверждённый пункт пробоподготовки один раз, в его собственный раздел. Для пункта с пометкой «Уточнить» явно показать, какая строка требует проверки, и пометить перечень как черновик. Дать скопировать весь перечень сразу. В табличном предпросмотре показывать номер, наименование с пунктами и количество. Количество с единицей и периодичностью пользователь вводит для конкретной позиции. Проверить, что значение «1 образец 2 раза в год» сохраняется в одной графе.
- Согласованный пример оформления для одной пробы с микробиологией и химией. Номера в примере иллюстрируют формат, фактические пункты берутся из карточки.

  > Салат из сырых овощей (р. VII, п. 32, 33, р. VIII, п. 36, 37)

- **Готово, когда** проверены одна и несколько проб, один и два раздела, дробный пункт, повтор пункта и пропущенный код. Две отдельные пробы остаются двумя строками. Пробоподготовка не дублируется при выборе нескольких показателей одной группы.

### 13. Реквизиты в заявлении

- В бланке сначала идут заказчик (юрлицо, ИП или гражданин), адрес регистрации, ИНН/КПП/ОГРН либо ОГРНИП и контакты. Далее блок представителя по договору или доверенности с именем или наименованием и контактами. Сохранять юридический адрес и фактический адрес или адреса отбора отдельными полями.
- После реквизитов идут выбранные работы (испытания, дополнительные протоколы и их число, отбор, экспертиза, число экспертных заключений, оферта, действующий договор с номером и датой), фактические адреса, объект испытаний, цель (производственный контроль, предписание, иное) и отметка о плановой проверке с периодом при наличии. Бланк также содержит отметки об ознакомлении, поручениях и возврате образцов, поле для нормативных документов, перечень исследований, список приложений, согласие и строку подписи. Пустые в заполненном образце поля и непроверенные отметки требуют решения при определении обязательности, без автозаполнения согласия.
- В предпросмотре объединить вручную введённые реквизиты и перечень этапа 12. Оставить возможность отдельно копировать перечень в действующий бланк.
- **Готово, когда** на обезличенном примере с разными адресами каждый адрес попадает в своё поле, правка реквизитов сохраняет список проб в открытом черновике, а перечень можно вставить в действующий бланк без ручной перегруппировки пунктов. Если бланк ещё не получен, точное оформление полного заявления остаётся на этапе 13, а перечень из этапа 12 уже можно проверять.

### 14. Печатная памятка на выезд

- Добавить предпросмотр памятки из того же черновика. Для каждой пробы вывести рабочее название, выбранные виды исследований, количество и единицы, документ по отбору и существенные условия из существующего плана. Использовать введённый адрес отбора. Если масса, объём или число порций не подтверждены, явно указать «Уточнить» рядом с соответствующей строкой. Вывести отдельно требования, которые относятся к разным исследованиям.
- Для годовой программы из рабочего примера дать выбрать первый или второй выезд и сформировать памятку на этот выезд. Позиции с двумя отборами включать в оба списка. Годовые позиции распределять вручную. Проверить отдельные строки для пищевых проб, смывов и инструментальных измерений. Ручные измерения используют число рабочих мест.
- Добавить печать из браузера с компоновкой для A4. Сохранить читаемый экранный вид на iPhone. Проверить сценарий выезда без сети в установленной PWA. Если требуется перенести готовую памятку с ПК на телефон, проверить открытие PDF, сохранённого через печать, после передачи файла.
- **Готово, когда** изменение и удаление пробы отражаются в обоих результатах, памятка с несколькими пробами читается при печати, адрес взят из поля отбора, а неполные сведения заметны в предпросмотре и на бумаге.

### 15. Опросник для сложной классификации

- Добавить действие «Помочь выбрать категорию» рядом с результатами поиска. Описать пилотные случаи через проверенные признаки и условия применимости карточек. Каждый вопрос привязать к тому, какие варианты он различает. Для многосоставного блюда вопросы могут касаться объекта испытаний, состава и обработки компонентов, если эти сведения влияют на выбор. Формулировки и ветвление сверить с контрольными примерами. При однозначном поиске можно сразу открыть карточку обычным способом.
- Показать найденные категории, основания и объяснение, какие признаки повлияли на результат. Предусмотреть ответ «Не знаю» и возможность изменить ответ. При неоднозначности показать оставшиеся варианты и недостающее условие. Если в проверенных данных нет подходящей категории, сообщить об этом и оставить переход к каталогу. Категорию выбирает пользователь, после чего пробу можно добавить в тот же черновик.
- **Готово, когда** сложный пример даёт сверенные карточки и понятное объяснение, неизвестный ответ не приводит к произвольному выбору, а выбранная карточка добавляется в заявление и памятку через существующий список проб.

## Решения для реализации

- **Границы `0.1`.** В первом импорте сохраняем байты выбранного HTML. Номер версии фиксируем тегом GitHub. Новые функции и переработка структуры идут отдельными изменениями после импорта.
- **Исходники.** GitHub хранит стабильную ветку `main` и отдельную ветку для каждой задачи. Work показывает изменения и результаты проверок в PR. Слияние после просмотра выполняет Макс. Для публичного репозитория включить доступную защиту `main` и успешные проверки перед слиянием. Для приватного репозитория технические ограничения зависят от тарифа.
- **Доставка.** Одна версия данных для двух сборок. Первый кандидат — GitHub Pages, если открытая публикация допустима и адрес работает на рабочем ПК. Запасной кандидат — Cloud.ru. Для закрытых данных нужен согласованный канал и, для PWA, HTTPS с контролем доступа. На Windows веб-версию можно использовать после проверки браузера, автономный HTML остаётся резервом.
- **Обновление.** В локальном HTML проверка зависит от доступа к HTTPS и заголовков CORS. Кнопка скачивает один версионный HTML. В PWA активная версия меняется после полной загрузки и проверки новой сборки. На iPhone проверка запускается при открытии. После очистки данных сайта понадобится заново открыть его онлайн.
- **Откат.** Хранить предыдущий HTML и кэш последней рабочей веб-версии. Для общего отката выпустить новый номер с восстановленным содержимым, чтобы устройства увидели обновление.
- **Действия после согласования.** Первую запись в GitHub, настройку хостинга и публикацию рабочих данных выполняем после отдельного разрешения. Доступность выбранного адреса с рабочей сети и iPhone подтверждается на этих устройствах.
