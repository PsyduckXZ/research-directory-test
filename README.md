# Справочник исследований

Тег `v0.1.0` фиксирует исходный HTML. Файлы для дальнейшей работы:

| Путь | Содержимое |
|---|---|
| `data/categories/01.json`–`09.json`, `water.json` | Карточки, нормативы, основания, отбор и прейскурант |
| `data/labels.json` | Названия разделов и видов исследований |
| `src/index.template.html`, `src/styles.css`, `src/app.js` | Разметка, оформление и поиск |
| `scripts/` | Проверка структуры и сборка |
| `research-directory-roadmap.md` | Дорожная карта |

Команды выполняются из корня репозитория на компьютере с Node.js. Сторонние пакеты для сборки не нужны.

```sh
node scripts/build.mjs --check
node scripts/build.mjs
```

Результат сборки — `dist/research-directory-sampling-trial.html`. Откройте его в браузере. Каталог, поиск и оформление находятся внутри файла. Режим предпросмотра без JavaScript получает карточки из того же каталога. Сборка не публикует сайт.

Исходный HTML в корне — копия первой версии. Для проверки новых изменений используйте файл из `dist/`.

Для ручной проверки найдите карточки `9.16.1.1`, `9.16.1.2.1` и `2.2.3`. Откройте микробиологию и отбор. Проверьте коды прейскуранта и одну строку пробоподготовки на группу.

## Тестовая PWA для iPhone

Команда `node scripts/build.mjs --pwa` собирает сайт в `dist/pwa/`.
Размещайте каталог целиком по HTTPS с сохранением структуры папок.
Для проверки добавьте сайт на экран «Домой», откройте его с иконки и
дождитесь сообщения «Справочник готов к работе без интернета».
Затем закройте приложение, отключите интернет и снова запустите его с иконки.

## Тест обновлений

```sh
node scripts/build.mjs --pwa --release=0.0.3-test --migrate dist/baseline/pwa/index.html
node scripts/build.mjs --release=0.0.3-test dist/baseline/windows/index.html
node scripts/build.mjs --pwa --release=0.0.4-test dist/update/pwa/index.html
node scripts/build.mjs --release=0.0.4-test dist/update/windows/index.html
```

Публикуйте PWA под существующим адресом `/pwa/`. Флаг `--migrate`
используется один раз для перехода со сборки без кнопки обновления.
Дальнейшие версии загружаются в отдельный кэш и могут быть применены
кнопкой после проверки всех файлов. При закрытии всех окон браузер
может активировать уже полностью загруженную версию при следующем запуске.

Для Windows публикуйте версионный HTML и его `version.json` в `/windows/`
одним развёртыванием. Храните предыдущие версионные HTML по их адресам.
Открывайте скачанный файл в актуальном Chrome или Edge. Версионный файл
содержит весь каталог в сжатом виде. Для поиска интернет не нужен.

## Веб-версия для компьютера

```sh
node scripts/build.mjs --web --release=0.0.5-test
```

Публикуйте `dist/web/` по HTTPS в каталоге `/desktop/`. Постоянная ссылка
открывает выпуск из `version.json`. Кнопка в шапке скачивает и проверяет
новую сборку целиком перед заменой страницы в той же вкладке. Запрос и
открытая карточка восстанавливаются, если карточка есть в новой выдаче.

Тест перехода между выпусками открывается с параметром `?test-baseline=1`.
На тестовом хостинге `baseline.json` указывает на предыдущую веб-сборку.
Обычное открытие ссылки загружает актуальный выпуск.

## Выпуск 0.1

```sh
node scripts/build.mjs --check
node scripts/build.mjs --web --release=0.1
node scripts/build.mjs --pwa --release=0.1
node scripts/build.mjs --release=0.1
```

Для перехода с тестовой веб-сборки, которая принимает только трёхкомпонентный номер, обновите вкладку браузера. Резервный тестовый HTML замените вручную один раз. В версии `0.1` кнопки проверки поддерживают двухкомпонентные и трёхкомпонентные номера.
